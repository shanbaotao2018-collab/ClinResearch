# 文献综述智能体 MVP 设计文档

## 1. 背景

目标是围绕医疗科研场景，建设一个“小切口、可闭环、可复用”的文献综述智能体示范应用。第一版不追求覆盖系统综述的全部流程，而是优先完成“检索 + 筛选”闭环，形成一个可演示、可审计、可复用的 B/S 工作台。

设计约束已经确定为：

- 工作台型 `B/S` 产品形态
- 第一版能力边界为 `检索 + 筛选`
- 检索源优先级为 `国外优先`
- 采用 `编排型 Agent`
- 采用 `现成 B/S 宿主 + 插件化接入`
- 部署边界为 `院内 / 私有化优先`

## 2. 目标与非目标

### 2.1 目标

第一版必须完成以下闭环：

1. 研究者创建一个文献综述项目。
2. 输入研究问题、PICO 和纳排标准草稿。
3. Agent 生成 PubMed 检索式，并支持人工确认。
4. 执行 `PubMed / Europe PMC` 检索，获取题录。
5. 支持导入中文数据库导出的题录文件。
6. 统一入库、去重、标题摘要筛选。
7. 记录纳排决策与理由。
8. 自动累计 PRISMA 所需计数并生成结果包。

### 2.2 非目标

以下内容明确不纳入第一版：

- 全文 PDF 批量解析
- 基线、效应量、结局数据抽取
- NOS / Cochrane 偏倚风险评价
- 自动撰写完整系统综述正文
- 复杂组织级科研管理或 BI 大屏
- 中文数据库正式授权直连

## 3. 方案比较与选型结论

### 3.1 宿主实现路径

方案 A：`Dify` 作为 B/S 宿主

- 优点：
  - 现成 Web 宿主完成度高
  - 多应用、多工作流、权限控制容易搭
  - 最适合先做可演示 MVP
- 缺点：
  - 不是医学科研专用工作台
  - 专业筛选和审阅界面仍需外挂或扩展

方案 B：`Flowise / Langflow` 作为编排宿主

- 优点：
  - 可视化编排直观
  - 便于快速验证工具链
- 缺点：
  - 工作台属性弱
  - 最终大概率还要补业务前端

方案 C：自建轻量工作台

- 优点：
  - 最贴业务流程
  - 后续扩展全文抽取更顺
- 缺点：
  - 不是最小开发量
  - 第一版交付更慢

### 3.2 选型结论

第一版采用：

- `Dify` 作为 B/S 工作台宿主
- 外接专业工具服务完成检索、筛选和 PRISMA 能力
- 采用编排型 Agent 组织流程

原因：

- 当前目标是最小代码量做出业务闭环，而不是自建最强 agent 引擎。
- `LangChain / LangGraph / OpenAI Agents SDK` 更适合作为后端编排层候选，而不是第一版直接充当工作台宿主。
- `Dify` 更适合先完成“有界面、有流程、有结果包”的 MVP。

## 4. 产品定位

产品名称暂定为：

- `文献综述智能体`

本质定位：

- 一个面向医疗科研的“检索与筛选工作台”
- 一个“可追溯、可复核”的科研流程 agent，而不是全自动科研黑盒

目标用户：

- 临床医生
- 科研助理
- 医院科研管理或数据支持团队

核心价值：

- 减少人工构造检索式的时间
- 减少人工整理题录、去重和筛选的重复劳动
- 形成标准化、可审计的筛选过程
- 为后续扩展全文抽取和系统综述写作打基础

## 5. 总体架构

总体采用四层结构：

### 5.1 第 1 层：B/S 工作台宿主

职责：

- 提供项目列表、任务入口、结果展示
- 承载用户交互和权限控制
- 承载 Agent 调用入口

实现建议：

- `Dify`

### 5.2 第 2 层：编排型 Agent 层

职责：

- 总控流程推进
- 控制状态切换
- 控制人工确认节点
- 调度专业工具服务

模式：

- `1 个总控 Agent + 4 个专用子 Agent`

### 5.3 第 3 层：专业工具服务层

职责：

- 提供专业检索、导入、筛选、PRISMA 能力

建议工具：

- `PubMed / Europe PMC` 检索服务
- `RIS / NBIB / BibTeX / CSV` 导入器
- `ASReview` 或 `AiReview`
- `PRISMA` 统计与出图服务

### 5.4 第 4 层：私有化数据层

职责：

- 保存项目事实数据
- 保存题录主表
- 保存去重结果
- 保存纳排决策与日志
- 保存 PRISMA 计数表

要求：

- 项目状态与审计数据必须完全落在私有环境

## 6. 工作台页面设计

第一版保持精简，只保留 5 个页面：

### 6.1 页面 1：项目列表页

展示：

- 项目名称
- 研究主题
- 当前阶段
- 题录数
- 筛选进度
- 最后更新时间

作用：

- 多项目管理入口

### 6.2 页面 2：新建项目页

录入：

- 研究问题
- PICO
- 纳排标准草稿
- 目标数据库范围

作用：

- 启动一个文献综述任务

### 6.3 页面 3：检索与筛选工作台

这是 MVP 核心页，包含 7 个步骤：

1. 研究问题与纳排标准
2. AI 生成检索式
3. 执行 `PubMed / Europe PMC` 检索
4. 导入中文题录文件
5. 去重与题录清洗
6. 标题摘要筛选
7. PRISMA 统计与导出

### 6.4 页面 4：结果导出页

导出内容：

- 题录清单
- 纳排结果
- PRISMA 数据表
- 过程报告

### 6.5 页面 5：审计日志页

记录：

- 检索式修改记录
- 检索执行记录
- 纳排判断记录
- PRISMA 生成记录

## 7. Agent 设计

### 7.1 总控 Agent

职责：

- 负责流程推进
- 负责状态切换
- 负责人工确认节点
- 汇总各子 Agent 输出

不负责：

- 存储项目事实
- 自己记忆 PRISMA 计数

### 7.2 选题拆解 / 检索式 Agent

输入：

- 研究问题
- PICO
- 纳排标准草稿

输出：

- PubMed 检索式
- 中文关键词串
- 检索式说明

适合 Agent 的原因：

- 需要医学术语理解、同义词扩展、布尔逻辑解释

### 7.3 检索执行 Agent

输入：

- 确认后的检索式
- 检索目标库

输出：

- 题录集合
- 来源标签
- 检索时间戳
- 检索报告

适合 Agent 的原因：

- 负责调用工具和解释结果，不承担自由裁量决策

### 7.4 去重筛选 Agent

输入：

- 题录集合
- 纳排标准

输出：

- 纳入 / 排除建议
- 排除理由草稿
- 待人工复核列表

适合 Agent 的原因：

- 标题摘要筛选需要语义理解

约束：

- 不直接替代研究者做最终纳排结论

### 7.5 PRISMA 汇总 Agent

输入：

- 各阶段计数
- 纳排日志

输出：

- PRISMA 数据表
- 流程摘要说明
- 导出说明

适合 Agent 的原因：

- 把结构化统计结果转成可读说明

## 8. Agent 与规则流的边界

### 8.1 交给 Agent 的内容

- 研究问题拆解
- 同义词与主题词扩展
- 检索式解释与优化建议
- 标题摘要语义判断建议
- 排除理由草稿生成
- PRISMA 过程摘要解释

### 8.2 必须固定成规则流的内容

- 项目状态机
- 题录去重规则
- 筛选阶段计数
- 纳排日志记账
- 导出文件结构
- 审计日志

### 8.3 关键原则

1. Agent 负责建议与解释，不负责最终业务事实判定。
2. 凡进入 PRISMA 和审计的数据，必须由规则流落库，不依赖 LLM 记忆。
3. 子 Agent 之间只共享结构化项目状态，不共享自由文本记忆。

## 9. 工具层设计

### 9.1 检索工具

能力：

- 执行 `PubMed / Europe PMC` 查询
- 拉取题录与摘要
- 保存原始查询与结果元数据

### 9.2 中文题录导入工具

第一版采用导入式方案：

- 支持 `RIS`
- 支持 `NBIB`
- 支持 `BibTeX`
- 支持 `CSV`

原因：

- 避免第一版直接碰 CNKI / 万方 / SinoMed 的授权与直连复杂度

### 9.3 筛选工具

候选：

- `ASReview`
- `AiReview`

职责：

- 提供标题摘要筛选建议
- 提供优先级排序
- 协助人工复核

### 9.4 PRISMA 工具

职责：

- 根据规则流计数生成 PRISMA 数据表与标准图

约束：

- 计数来源只能是项目数据库中的结构化统计结果

## 10. 数据模型与状态流

### 10.1 核心数据对象

至少需要以下对象：

- `Project`
- `ResearchQuestion`
- `SearchStrategyVersion`
- `Citation`
- `CitationImportBatch`
- `DedupResult`
- `ScreeningDecision`
- `PrismaCount`
- `AuditLog`

### 10.2 最小状态流

建议项目阶段：

1. `draft`
2. `search_strategy_ready`
3. `search_executed`
4. `citations_deduplicated`
5. `screening_in_progress`
6. `screening_completed`
7. `prisma_generated`
8. `exported`

### 10.3 最小数据流

1. 用户输入研究问题并创建项目。
2. 检索式 Agent 生成检索式并保存版本。
3. 检索执行 Agent 拉取英文题录并入题录主表。
4. 用户上传中文题录文件并统一入库。
5. 规则流执行去重，生成唯一题录集。
6. 去重筛选 Agent 产生筛选建议。
7. 人工确认纳排后，规则流累计计数。
8. PRISMA 汇总 Agent 读取计数表并生成导出结果。

## 11. 人机协同设计

第一版必须保留 3 个确认点：

1. 检索式执行前
2. 标题摘要纳排时
3. PRISMA 最终出图前

原因：

- 第一版目标是“可追溯、可复核”的工作台
- 不是全自动科研代理

## 12. 错误处理与审计要求

### 12.1 错误处理

系统至少要处理：

- 检索接口失败
- 导入文件格式错误
- 题录字段缺失
- 去重异常
- 筛选引擎返回不完整结果
- PRISMA 计数不一致

策略：

- 所有失败都要记录到 `AuditLog`
- 可重试步骤应支持重新执行
- 不允许失败后隐式覆盖已有项目事实数据

### 12.2 审计要求

必须记录：

- 谁创建了项目
- 谁修改了检索式
- 谁执行了检索
- 谁做了纳排判断
- 谁生成了 PRISMA
- 每次动作发生时间与输入摘要

## 13. 验收标准

第一版完成的判断标准：

1. 能创建并管理多个综述项目。
2. 能基于研究问题生成可编辑的 PubMed 检索式。
3. 能执行 `PubMed / Europe PMC` 检索并保存题录。
4. 能导入中文题录文件并与英文题录统一管理。
5. 能完成去重和标题摘要筛选。
6. 能记录纳排决策与理由。
7. 能基于结构化计数生成 PRISMA 结果。
8. 能导出结果包并保留完整审计痕迹。

## 14. 后续演进路径

在第一版跑通后，推荐按以下顺序扩展：

### 14.1 第二阶段

- 全文 PDF 获取与解析
- 研究设计识别
- 基线 / 结局 / 效应量抽取
- 人工复核台增强

### 14.2 第三阶段

- NOS / ROB2 / ROBINS-I 模板化评价
- 偏倚风险可视化
- 研究脉络与争议点总结
- 系统综述初稿生成

## 15. 一句话结论

第一版“文献综述智能体”不是一个大而全的科研平台，而是一个基于 `Dify` 宿主、采用编排型 Agent、复用专业检索与筛选组件、面向医疗科研检索与筛选闭环的私有化工作台。
