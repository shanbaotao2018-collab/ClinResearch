# 临床科研智能体工作台：四个 Agent 使用与术语说明

> 适用对象：刚开始接触临床科研和 AI 智能体的研究者。
>
> 本文只说明当前项目已经实现的能力。所有研究设计、文献筛选、证据评价和写作结果均为“辅助草稿”，不能替代研究者、统计师、伦理委员会或临床决策。

## 1. 先用一句话理解四个 Agent

本工作台把一项临床科研工作拆成四段。每一段由一个专门的 Agent 负责，上一段的项目记录可作为下一段的正式输入。

| Agent | 它解决什么问题 | 你给它什么 | 它交付什么 | 不能替你决定什么 |
|---|---|---|---|---|
| `study-design-agent` 研究设计 Agent | 把一个模糊想法变成可讨论的研究方案草稿 | 研究方向、疾病、人群、干预或暴露、可用病例资源、研究目标 | 研究问题、PICO、研究类型建议、纳排标准、结局、样本量、随机化方案、方案大纲 | 最终方案、伦理审批、样本量假设、正式随机分配 |
| `literature-review` 文献检索与综述 Agent | 找到候选研究，并把检索和筛选过程留痕 | 研究问题、PICO、纳入和排除标准 | 检索式、题录、去重结果、筛选建议、PRISMA 计数、研究脉络、综述大纲 | 最终纳入或排除哪些文章 |
| `evidence-extraction-agent` 证据抽取与系统评价 Agent | 把已纳入文章的资料整理成可核对的证据表 | 已完成筛选的文献项目、摘要或合法取得的全文 | 基线表、结局表、效应指标、文献安全检查、初步偏倚风险评价、符合条件时的 Meta 分析 | 没有原文支持的任何数值、最终质量结论、最终系统评价 |
| `research-writing-agent` 科研写作 Agent | 基于已保存的项目事实，形成可修改的写作草稿 | 研究设计项目、已完成证据抽取的综述项目，或两者关联的研究案例 | 方案、标书、方法学段落或讨论框架草稿；来源清单和待补事项 | 把草稿当成正式申报书、论文、伦理材料或临床建议 |

## 2. 四个 Agent 如何衔接

不是每个课题都必须从头跑完四个 Agent。例如，已有成熟研究方案时，可以直接从文献综述开始；已有数据和研究方案时，可以直接进行科研写作。

```mermaid
flowchart LR
    A[研究想法或临床问题] --> B[研究设计 Agent]
    B -->|研究设计项目| C[文献检索与综述 Agent]
    C -->|已确认纳入的文献项目| D[证据抽取与系统评价 Agent]
    B -->|已保存的设计内容| E[科研写作 Agent]
    D -->|已完成的证据表| E
    C -->|仅筛选建议，需人工确认| D
    E --> F[人工复核后的研究材料]
```

四段工作的核心交接物如下：

| 上一步 | 保存的交接物 | 下一步如何使用 |
|---|---|---|
| 研究设计 | `study-design` 项目：PICO、方案蓝图、样本量假设、方案草稿 | 写作 Agent 可据此起草 protocol、proposal 或 methods |
| 文献综述 | `review` 项目：检索式、题录、去重记录、人工确认后的纳入/排除决定 | 证据抽取 Agent 只处理其中标为 `include` 的文章 |
| 证据抽取 | 证据表、全文来源清单、偏倚风险初评、可选 Meta 分析 | 写作 Agent 用这些已保存事实起草讨论或综述相关内容 |
| 科研写作 | 草稿、来源清单、未解决事项、审批状态 | 研究者继续补充、审核和导出，不会自动变成正式成果 |

## 3. 先认识几个关键原则

### 3.1 Agent、Skill 和 Tool 不是什么关系

| 名称 | 白话解释 | 本项目中的作用 |
|---|---|---|
| Agent（智能体） | 一个负责完成特定任务的“工作角色”。它会理解目标、按步骤安排工作、调用能力并汇总结果。 | 四个主 Agent 分别负责设计、检索综述、证据抽取、写作。 |
| 主 Agent（Primary Agent） | 面向研究者的主负责人，负责把一段工作从开始推进到可交付状态。 | 你在 OpenCode 下拉菜单中选择的四个 Agent。 |
| 子 Agent（Subagent） | 由主 Agent 临时委托的专门助手。 | 文献综述 Agent 会委托 `search-agent` 优化检索式、委托 `screening-agent` 给出标题摘要筛选建议。 |
| Skill（技能） | 一份明确的专业工作说明和约束，不是单纯的一段提示词。它规定该怎么做、哪些内容不能编造、输出要包含什么。 | 例如 `sample-size-basic` 约束样本量计算，`retraction-watcher` 约束撤稿检查。 |
| Tool（工具） | 能真正执行或保存动作的接口，例如创建项目、检索题录、计算样本量、导出文件。 | 通过 MCP 工具把结果写入本地后端，而不是只显示在聊天里。 |
| MCP | Model Context Protocol 的缩写，是让 OpenCode 和后端工具以统一方式通信的协议。 | 本项目的 MCP 把 Agent 连接到本地科研项目库、检索、导入、抽取和导出能力。 |
| 后端服务 | 在本机或服务器上持续运行的程序，负责保存项目、执行工具、管理在线/离线文献访问。 | 当前统一后端为 FastAPI 服务，MCP 地址通常是 `http://127.0.0.1:8010/mcp/`。 |
| 工作流（Workflow） | 为防止遗漏步骤而设定的执行顺序。 | 每个 Agent 都有固定链路，例如“创建项目→保存内容→确认→导出”。 |
| 工作流运行编号（`workflow.run_id`） | 某一次任务的唯一追踪号。 | 后续工具调用会带上它，系统可判断这些动作是否属于同一项研究任务。 |
| 项目记录（System of Record） | 被系统认定为正式依据的本地记录。 | 聊天中说过的话不等于已保存；只有写入研究设计项目、综述项目或证据表的内容才能供下一步使用。 |
| Skill 执行回执（Skill Receipt） | 系统留下的“本次确实调用过这个技能”的证据。 | 后端会校验关键 Skill 回执，避免 Agent 只靠自由发挥就写入正式项目记录。 |

### 3.2 三种结果状态必须分清

| 状态 | 含义 | 例子 |
|---|---|---|
| 系统已核验 | 来自工具返回或已保存记录，可追溯。 | 已导入 12 条题录、去除了 2 条重复记录。 |
| Agent 草稿或建议 | AI 根据输入和 Skill 生成，仍需要研究者判断。 | 建议将“30 天再入院”设为主要结局。 |
| 研究者已确认 | 研究者在当前任务中明确同意，系统才允许进入下一关键步骤。 | 确认某篇文献纳入，或确认样本量的事件率假设。 |

## 4. Agent 一：研究设计 Agent

### 4.1 它适合解决什么问题

当你只有一个临床想法，例如“药师出院后随访是否能降低心衰患者再入院”，但还不知道研究类型、研究对象、结局和样本量怎么写时，使用 `study-design-agent`。

它目前支持诊断、干预/疗效、病因和预后方向的研究设计草案。它会把想法整理成一份可以和导师、统计师或伦理秘书沟通的研究设计底稿。

### 4.2 你需要准备什么输入

| 建议提供的信息 | 示例 |
|---|---|
| 临床或科研问题 | 心衰患者出院后，药师过渡管理能否降低 30 天再入院？ |
| 研究场景 | 心内科、住院患者、单中心或多中心 |
| 目标人群 | 成人心衰住院患者 |
| 干预、暴露或检测方法 | 药物重整、用药教育、随访；或某项检查指标 |
| 对照对象 | 常规出院指导；未暴露组；金标准检查 |
| 希望观察的结局 | 再入院、死亡、生活质量、诊断准确性等 |
| 资源条件 | 可招募人数、预计研究周期、是否能随机分组 |
| 数据安全声明 | 只输入去标识化或汇总数据；不要输入姓名、住院号、电话等身份信息。 |

### 4.3 它实际会做哪些步骤

1. 澄清研究目标、科室场景、资源限制和研究类型。
2. 将问题整理为 PICO。
3. 创建一个新的本地研究设计项目，后续内容都保存到此项目。
4. 生成研究设计蓝图，提示适合的报告规范和必备章节。
5. 起草纳入/排除标准、主要与次要结局、创新性、可行性和方案大纲。
6. 将草稿保存为项目记录。
7. 用明确展示的假设参数，计算基础两组比较样本量。
8. 如果明确是 RCT，保存随机化方案，但此时不生成也不展示分配表。
9. 展示设计摘要后，调用一次 OpenCode 原生 `Allow/Deny` 确认。允许后，系统才会完成审批、生成受保护的随机分配表并导出方案包。

### 4.4 它会交付什么

| 交付物 | 你可以怎么理解 |
|---|---|
| 研究问题 | 用一句可回答的话写清“谁、做什么/有什么暴露、与谁比、看什么结果”。 |
| 研究类型建议 | 例如 RCT、队列研究、诊断准确性研究或预后研究，并说明适用的报告规范。 |
| PICO | 用标准框架固定研究对象、干预、对照和结局。 |
| 纳入/排除标准草案 | 告诉未来如何判断一个患者或病例能否进入研究。 |
| 结局定义 | 明确主要结局、次要结局、观察时间点和测量方式。 |
| 样本量结果 | 显示每组人数、总人数以及采用的 alpha、把握度和事件率等假设。 |
| 随机化方案 | 对 RCT，说明分层、区组等分配原则；具体分配序列由受保护后端保存，不展示给 Agent。 |
| 方案大纲 | 可用于继续完善研究方案或标书的章节框架。 |

### 4.5 使用的主要 Skills

| Skill | 它负责的专业工作 |
|---|---|
| `phi-prompt-guard` | 检查输入是否可能包含患者身份信息，要求使用去标识化或汇总数据。 |
| `clinic-research-design` | 组织临床科研问题、研究类型和设计要素。 |
| `inclusion-criteria-gen` | 起草纳入和排除标准。 |
| `research-proposal-generator` | 生成研究方案或标书的内容框架。 |
| `sample-size-basic` | 规范基础两组样本量的假设与表达。 |
| `randomization-gen` | 为 RCT 设计随机化规则，不直接暴露分配结果。 |
| `biomed-outline-generator` | 生成医学研究写作大纲。 |
| `method-writing` | 起草方法学描述。 |

### 4.6 必须人工确认的内容

- 纳入和排除标准是否符合真实临床路径。
- 主要结局是否具有临床意义且可获得。
- 样本量的对照组事件率、预期效应、alpha 和把握度是否合理。
- 是否真的采用 RCT，以及随机化方案是否可执行。
- 是否允许导出方案包。

### 4.7 当前 MVP 的边界

当前样本量工具只支持“等比例分配的两组均值比较”或“等比例分配的两组率比较”。不支持生存时间、整群随机、非劣效、多臂或自适应设计的样本量计算。遇到这类研究，Agent 会说明限制，研究者应交由统计师使用合适的软件复核。

### 4.8 可直接使用的指令示例

```text
我想研究“心衰患者出院后药师电话随访是否降低 30 天再入院”。
场景是单中心心内科，预计可招募约 600 名成人患者，拟与常规出院指导比较。
请完成研究设计、PICO、纳排标准、主要和次要结局、两组比例样本量及随机化方案。
所有数据均为演示用去标识化汇总信息。
```

## 5. Agent 二：文献检索与综述 Agent

### 5.1 它适合解决什么问题

当你已经有研究问题，想知道“应该怎么查文献、找到了什么、哪些值得进一步看、目前研究有什么争议”时，使用 `literature-review`。

它不是普通搜索框：它会把检索式、数据库来源、导入题录、去重和筛选建议都放进一个可追溯的本地综述项目中。

### 5.2 你需要准备什么输入

| 建议提供的信息 | 示例 |
|---|---|
| 综述问题 | 药师主导出院过渡管理是否改善心衰患者再入院？ |
| PICO | 成人心衰患者；药师主导过渡管理；常规出院管理；再入院或死亡。 |
| 初步纳入标准 | RCT 和队列研究；成人；报告再入院结局。 |
| 初步排除标准 | 综述、社论、无可用结局的文章。 |
| 访问模式 | 正常部署可用 online/auto 检索；演示或医学数据库不可达时可用 offline 本地证据包。 |

### 5.3 它实际会做哪些步骤

1. 澄清问题并生成 PICO。
2. 创建本地综述项目。
3. 生成基础检索策略。
4. 委托 `search-agent` 使用检索专业 Skills 进行同义词扩展和布尔逻辑优化。
5. 检查当前文献访问状态。
6. 在线/自动模式下经统一后端检索 PubMed，必要时检索 Europe PMC；离线模式下展示本地离线证据包，由研究者选择后导入原始题录。
7. 将题录导入项目并执行去重。
8. 委托 `screening-agent` 基于标题和摘要给出初筛建议与理由。
9. 展示建议，等待研究者逐条或批量明确确认。
10. 只有确认后，才把 `include`、`exclude` 或 `human_review` 写入项目，并导出综述包。
11. 根据实际保存的数据，输出检索概览、PRISMA 计数、证据模式、争议点和综述大纲。

### 5.4 它会交付什么

| 交付物 | 作用 |
|---|---|
| 检索策略草案 | 可复制到数据库执行的关键词、主题词和布尔组合。 |
| 推荐数据库 | 说明 PubMed、Europe PMC 或本地离线证据包各自承担什么角色。 |
| 题录导入与去重结果 | 说明检索了多少、导入了多少、删掉了多少重复记录。 |
| 标题摘要筛选建议 | 每条候选文献的建议决定、理由和置信度，但不是最终决定。 |
| PRISMA 快照 | 用数字展示检索、去重、筛选、纳入等流程进度。 |
| 证据总结与争议点 | 基于当前已获取的题录或摘要，区分事实、推断和待验证事项。 |
| 综述大纲 | 为后续系统评价或叙述性综述写作提供章节结构。 |

### 5.5 使用的主要 Skills 和子 Agent

| 名称 | 它负责的工作 |
|---|---|
| `search-agent` | 子 Agent。优化检索策略并返回执行过的 Skill 回执。 |
| `pubmed-search-specialist` | 将自然语言问题变成更符合 PubMed 习惯的英文检索式。 |
| `reference-search` | 扩展同义词、相关术语和布尔组合。 |
| `screening-agent` | 子 Agent。根据标题和摘要提出筛选建议。 |
| `systematic-review-screener` | 规范系统综述的初筛判断过程。 |
| `literature-filtering` | 让纳入/排除理由与预先设定标准对应。 |
| `citation-chasing-mapping` | 用于后续追溯参考文献或分析引用关系。 |
| `retraction-watcher` | 提醒检查撤稿或关注声明。 |
| `literature-review`、`systematic-review` | 约束综述工作流和证据表达方式。 |

### 5.6 必须人工确认的内容

- 检索式是否符合你的研究问题与语言范围。
- 纳入和排除标准是否锁定。
- 每一篇文献是否真的纳入或排除。

Agent 可以提出“建议纳入”，但不会把它自动当成项目事实。研究者明确确认前，项目状态仅是“筛选建议已准备好”。

### 5.7 当前真实文献源：权威性、能力与边界

当前联网版已经真实接入两个公开来源：`PubMed` 与 `Europe PMC`。在
`client_online` 部署中，检索和开放全文预检由研究者桌面端的本地连接器发起，
后端负责保存项目、题录、全文状态、审计记录和导出结果。因此，服务端无法访问
医学数据库时，不会阻断桌面端的真实检索。

| 来源 | 权威性和常见定位 | 当前可用能力 | 不能替代什么 |
|---|---|---|---|
| PubMed | 美国国家医学图书馆（NLM）/NCBI 维护的免费生物医学检索资源；MEDLINE 是其最大组成部分，带有 MeSH 等人工标引。官方说明其收录超过 4,000 万条题录和摘要。 | 真实题录检索、英文检索式、PMID/DOI 元数据核验、撤稿公告类型检查。 | PubMed 主要提供题录和摘要，不保证全文，也不能充分覆盖中文本土研究。 |
| Europe PMC | EMBL-EBI 运营的免费生命科学文献平台，提供论文、预印本、数据和开放全文的关联；官方介绍约有 4,620 万条记录。 | 补充题录检索、开放全文状态预检、合法开放 XML 全文获取与缓存。 | 与 PubMed/PMC 有大量重叠；不能把两者简单看成两套完全独立的证据库，也不能保证每篇文章都有开放全文。 |

官方资料：

- [PubMed About](https://pubmed.ncbi.nlm.nih.gov/about/)
- [Europe PMC About](https://europepmc.org/about)
- [Europe PMC Help: free full text filters](https://europepmc.org/help)

**当前结论：** 两个来源足以支撑第一版本的真实联网演示，以及大多数英文医学课题的“检索、去重、筛选、开放全文预检、证据抽取”闭环；但不应宣称已经完成正式系统综述所需的全面数据库覆盖。

### 5.8 国内常用来源与合规接入方式

国内临床科研通常还会使用以下来源补齐中文研究、学位论文、会议资料和本土实践证据。它们不是当前已接入能力，必须在医院或高校已有授权的前提下接入。

| 来源 | 典型价值 | 接入原则 |
|---|---|---|
| SinoMed / CBM | 最贴近医学信息检索的中文/中外文生物医学资源。SinoMed 由中国医学科学院医学信息研究所/图书馆建设，提供检索、开放获取和文献传递等服务。 | 优先调研医院是否已有授权、机构登录或正式接口；不通过网页爬取绕过权限。 |
| CNKI（中国知网） | 覆盖中文期刊、学位论文和会议资料，是国内常见学术资源入口。 | 通过医院图书馆授权、厂商接口，或由研究者合规导出 RIS/EndNote 文件再导入。 |
| 万方医学网 / 万方数据 | 补充中文医学期刊、临床知识和会议、学位等资源。 | 同样采用机构订阅、正式接口或合规文件导入。 |
| 维普（VIP） | 中文期刊补充来源，适合与知网、万方交叉核对。 | 需确认机构订阅范围和可用导出方式。 |

参考入口：[SinoMed 中国生物医学文献服务系统](https://www.sinomed.ac.cn/main.jsp)。

对中文来源，产品应提供两种合规模式：

1. **授权连接器模式**：医院提供供应商 API、单点登录或图书馆代理授权后，由连接器检索并保留来源标签。
2. **研究者导入模式**：研究者在有权限的数据库完成检索，导出 RIS、NBIB、EndNote 或 CSV；系统导入后继续执行去重、筛选、PRISMA 和证据抽取。

不得将“用户可以在浏览器里访问”误解为系统可以批量抓取全文的授权。

### 5.9 后续可扩展来源与优先级

| 优先级 | 来源 | 能补齐什么 | 接入判断 |
|---|---|---|---|
| P0 | OpenAlex | 跨学科补充检索、引文网络、相似研究发现和开放获取定位。 | 技术接入成本低；需申请 API Key，适合作为查漏和引文追踪来源，而不是医学主检索库。 |
| P0 | ClinicalTrials.gov | 已注册、进行中、未发表或延迟发表的临床试验。 | 可直接接入；用于减少只看已发表结果造成的偏倚，不替代论文数据库。 |
| P1 | Crossref / Semantic Scholar | DOI 元数据补全、引用关系与相似论文发现。 | 适合作为题录补全和追溯工具，不作为医学证据唯一来源。 |
| P1 | Embase | 药物、药物警戒、欧洲期刊和会议摘要覆盖。 | 对药物类系统综述价值高，但通常需要医院或高校的商业订阅。 |
| P1 | Cochrane Library / CENTRAL | 高质量系统综述和临床试验索引。 | 需要按机构订阅和再利用规则接入。 |
| P2 | Web of Science / Scopus | 被引分析、引用网络和跨学科覆盖。 | 商业授权后接入，优先服务文献计量与查漏场景。 |

OpenAlex 官方说明其提供开放学术索引与 REST API；ClinicalTrials.gov 提供公开数据 API：

- [OpenAlex Developers](https://developers.openalex.org/)
- [ClinicalTrials.gov Data API](https://clinicaltrials.gov/data-api/api)

建议的产品扩展顺序是：**保持 PubMed + Europe PMC 作为英文医学基础层 -> 接入 OpenAlex 与 ClinicalTrials.gov -> 对接医院已授权的 SinoMed/CNKI/万方 -> 有明确系统综述需求后接入 Embase、Cochrane、Web of Science 或 Scopus。**

### 5.10 在线、离线和自动模式的区别

| 模式 | 数据来源 | 适用情况 | 后续工作流 |
|---|---|---|---|
| `client_online` | PubMed、Europe PMC 等在线医学数据库 | 研究者桌面端可访问数据库 | 桌面本地连接器检索真实题录，后端保存项目状态和结果。 |
| `online` | PubMed、Europe PMC 等在线医学数据库 | 服务端能正常访问数据库 | 后端检索到真实题录后导入项目。 |
| `offline` | 本地离线证据包中的原始题录、允许提供的全文资源 | 内网环境无法访问医学数据库，或用于固定演示案例 | 研究者选择本地包导入，后续去重、筛选、抽取逻辑与在线模式一致。 |
| `auto` | 优先尝试在线来源；不可达时停止反复重试并可转本地包 | 网络条件不稳定 | 后端统一判断访问状态，避免 Agent 绕过策略自行网络搜索。 |

### 5.11 可直接使用的指令示例

```text
请围绕“药师主导的心衰患者出院过渡管理，相较常规出院管理，
是否改善再入院率或临床结局”开展一项文献综述。
人群为成人心衰住院患者，关注再入院、死亡和急诊就诊；
纳入 RCT、队列和准实验研究，排除综述与无结局数据的文章。
请先完成检索、导入、去重和标题摘要筛选建议；在保存纳入/排除决定前向我确认。
```

## 6. Agent 三：证据抽取与系统评价 Agent

### 6.1 它适合解决什么问题

当文献综述项目中已经有研究者确认的 `include` 文献时，使用 `evidence-extraction-agent`。它的任务不是再找文献，而是把每篇纳入文章中“能被原文支持的信息”统一填入证据表，以便比较研究设计、基线、干预和结局。

### 6.2 它开始前需要满足的条件

- 已有完成初筛并保存决定的综述 `project_id`。
- 需要抽取的文献必须在项目中标记为 `include`。
- 至少有题录、摘要，或研究者合法提供的全文片段/全文。
- 如果要做全文抽取、偏倚风险评价或 Meta 分析，必须提供研究者上传的全文、公开可访问 HTML，或离线包内允许使用的全文资源。

### 6.3 它实际会做哪些步骤

1. 启动证据抽取工作流，并绑定对应的综述项目。
2. 从本地题录、摘要或研究者提供的全文片段中提取研究信息和方法信息。
3. 对每篇纳入文献保存一行或多行证据记录，并写清证据依据是 `metadata`、`abstract` 还是 `full_text_excerpt`。
4. 把原文没有报告的项目放进缺失字段，最终展示为 `not_reported`，而不是猜测一个值。
5. 执行撤稿/关注声明检查并保存检查时点。
6. 所有纳入文献完成基础抽取和安全检查后，导出基础证据表。
7. 在研究者确认要进行全文系统评价后，才进入全文处理、基线/结局抽取、偏倚风险初评和可选 Meta 分析。
8. 系统评价包导出前需要研究者审核范围，并在 OpenCode 的 `Allow/Deny` 权限提示中确认。

### 6.4 它会交付什么

| 交付物 | 作用 |
|---|---|
| 证据表 | 每篇已纳入研究的设计、对象、方法、结局、效应指标及缺失信息。 |
| 证据依据 | 明确某个字段来自题录、摘要还是全文片段，便于复核。 |
| 文献安全检查摘要 | 记录撤稿或相关公告的检查结果和检查时间。 |
| 全文来源清单 | 记录全文是研究者提供、公开网页还是离线包资源。 |
| 基线和结局提取表 | 对有全文依据的研究，结构化列出两组基线、事件数、总人数、时间点等。 |
| 初步偏倚风险评价 | 依据研究类型使用 RoB 2、NOS 或 QUADAS-2，并保留原文定位与理由。 |
| 二分类 Meta 分析和森林图 | 只有至少两项研究具有可比的二分类结局和 RR/OR 时才生成。 |

### 6.5 使用的主要 Skills

| Skill | 它负责的工作 |
|---|---|
| `clinical-study-info-extractor` | 提取研究对象、设计、干预、对照和结局等基本信息。 |
| `methodology-extractor` | 提取研究方法、随访、分析方法等。 |
| `retraction-watcher` | 查询或记录文献在检查时点是否有撤稿/关注提示。 |
| `meta-screening-fulltext` | 在进入全文系统评价前，核对全文是否满足预设标准。 |
| `fulltext-fetcher` | 获取公开可访问的 HTML 全文；不能绕过付费墙。 |
| `pdf-extract` | 从研究者提供或允许使用的 PDF 中提取文本。 |
| `baseline-extraction-for-clinical-trials` | 提取临床试验的基线特征。 |
| `outcome-extraction-for-clinical-trials` | 提取结局事件数、总人数、时间点和效应指标。 |
| `rct-bias-assessment-rob` | 对随机对照试验进行 RoB 2 初步评价。 |
| `cohort-study-quality-assessment-nos` | 对队列研究进行 NOS 初步评价。 |
| `diagnostic-study-quality-assessment-quadas` | 对诊断准确性研究进行 QUADAS-2 初步评价。 |
| `meta-analysis` | 对满足条件的数据执行合并分析。 |
| `meta-forest-binary-plot` | 生成二分类结局的森林图。 |

### 6.6 必须人工确认的内容

- 摘要级信息是否足以支撑当前结论。
- 全文来源是否合法、完整且与该题录对应。
- 每个基线和结局字段是否与原文一致。
- 偏倚风险评价的每个判断和理由。
- 是否可以把当前证据表作为系统评价包导出的范围。

### 6.7 当前 MVP 的边界

基础抽取可从题录、摘要和用户提供的全文片段开始，但摘要不能被当作全文。Meta 分析仅支持至少两项研究的、结局和效应指标相同的二分类 RR 或 OR 合并；暂不合并 HR、连续变量、诊断准确性、网络 Meta、亚组或个体患者数据。

撤稿检查结果为“在检查时点未被标记”时，只表示当时未发现提示，不代表该文献永久安全或质量无问题。所有证据行默认仍需要研究者按全文复核。

### 6.8 可直接使用的指令示例

```text
请对综述项目 12 中已确认纳入的文献进行证据抽取。
请先导出基于题录和摘要的证据表，逐项标明证据依据和缺失字段，
并完成文献安全检查。不要猜测未报告的数值。
如需全文，请列出需要我提供的文章和具体字段；
在任何系统评价导出前向我请求确认。
```

## 7. Agent 四：科研写作 Agent

### 7.1 它适合解决什么问题

当研究设计或证据表已经保存，想把这些“已知事实”组织成研究方案、标书、方法学段落或讨论框架时，使用 `research-writing-agent`。

它的核心原则是：只基于已保存来源写作。没有来源的数据、引用、伦理状态、预算或结果，不会被补写成事实，而会明确列为待补内容。

### 7.2 它能写什么

| 文档类型 | 适用来源 | 主要内容 |
|---|---|---|
| `protocol` 研究方案 | 已保存的研究设计项目 | 研究背景、对象、流程、结局、统计计划占位等。 |
| `proposal` 课题/标书草案 | 研究设计项目，必要时关联证据项目 | 立项依据、科学问题、创新性、研究内容和技术路线。 |
| `methods` 方法学草稿 | 研究设计项目或有完整证据表的综述项目 | 研究对象、数据来源、变量、分析方法和质量控制的草稿。 |
| `discussion` 讨论框架 | 已完成证据抽取的综述项目 | 主要发现、证据强弱、局限性、争议和后续研究方向。 |

### 7.3 它实际会做哪些步骤

1. 确定写作来源：研究设计项目、已完成证据抽取的综述项目，或同时关联两者的 `research_case`。
2. 从后端读取该来源已经保存的事实，而不是从聊天记忆中补全。
3. 确认文档类型，并说明输出只是草稿。
4. 启动写作工作流，调用大纲、方法写作、讨论结构等 Skills。
5. 建立来源清单，逐条记录项目类型、项目编号和使用内容。
6. 生成草稿；对缺少的数据、参考文献、审批、预算或结果保留占位符和待解决事项。
7. 保存草稿到本地项目。
8. 展示审批范围，研究者审核后，在 OpenCode `Allow/Deny` 中确认。
9. 后续运行确认审批状态后，才允许导出写作包。

### 7.4 它会交付什么

| 交付物 | 作用 |
|---|---|
| 文档大纲 | 帮你确认文章或方案是否结构完整。 |
| 方法学草稿 | 将已确认的研究对象、设计和分析计划组织成规范叙述。 |
| 讨论框架 | 将已抽取证据组织为发现、解释、局限性和研究空白。 |
| 标书草稿 | 在请求 `proposal` 时，形成研究内容、技术路线和可行性等草案。 |
| 来源清单（Source Manifest） | 让每份草稿可追溯到具体项目和证据，而不是“AI 自己说的”。 |
| 局限性与待解决事项 | 明确哪些内容仍需你补证据、补数据或走审批。 |

### 7.5 使用的主要 Skills

| Skill | 它负责的工作 |
|---|---|
| `biomed-outline-generator` | 生成医学科研文稿的章节与逻辑框架。 |
| `method-writing` | 将研究设计、对象和分析计划写成方法学草稿。 |
| `discussion-section-architect` | 构建讨论部分的论证顺序、局限性和研究空白。 |
| `research-proposal-generator` | 仅在写 `proposal` 时使用，用于生成课题/标书结构。 |

### 7.6 必须人工确认的内容

- 草稿引用的来源是否完整、准确。
- 占位符和未解决事项是否都已处理。
- 方法学、伦理、注册、预算、团队分工等陈述是否有真实依据。
- 是否允许导出写作包。

### 7.7 可直接使用的指令示例

```text
请以已保存的 study-design 项目 8 为唯一事实来源，起草一份 protocol。
需要包含研究问题、PICO、纳排标准、结局、样本量假设和随机化原则。
没有来源支持的内容请写成待补事项，不要补造引用、伦理审批状态或临床结论。
保存草稿后向我展示来源清单和待确认事项。
```

## 8. 专业术语词典：研究设计

| 术语 | 白话解释 | 在本项目里怎么用 |
|---|---|---|
| 研究问题（Research Question） | 一句能够通过研究回答的问题。 | 是四个 Agent 的起点；越具体，输出越可用。 |
| PICO | 把临床问题拆成 P（人群）、I（干预/暴露）、C（对照）、O（结局）。 | 研究设计和文献综述都会生成并保存 PICO。 |
| P：Population | 研究对象是谁。 | 如“成人心衰住院患者”。 |
| I：Intervention/Exposure | 接受什么干预，或有什么暴露/特征。 | 如“药师过渡管理”；观察性研究中也可指暴露因素。 |
| C：Comparator | 用来比较的对象。 | 如“常规出院指导”或“未暴露组”。 |
| O：Outcome | 要观察的结果。 | 如“30 天全因再入院”。 |
| 纳入标准（Inclusion Criteria） | 满足哪些条件的人或研究可以进入。 | Agent 生成草案，研究者确认后才可视为最终标准。 |
| 排除标准（Exclusion Criteria） | 哪些情况不能进入研究。 | 用于减少不适合对象对结果的干扰。 |
| 结局（Outcome） | 衡量研究效果或状态变化的指标。 | 应说明定义、时间点和测量方式。 |
| 主要结局（Primary Outcome） | 最核心、决定研究主要结论的结局。 | 样本量通常围绕它设计。 |
| 次要结局（Secondary Outcome） | 补充理解干预效果或安全性的结局。 | 不应随意替代主要结局。 |
| 研究类型（Study Type） | 回答问题所采用的研究方法类别。 | Agent 会根据目标建议适合的类型。 |
| RCT | Randomized Controlled Trial，随机对照试验。参与者按随机规则进入不同组，以比较干预效果。 | 只有明确为 RCT 时，才会保存随机化计划。 |
| 队列研究（Cohort Study） | 观察一群人随时间发生什么，比较不同暴露组的结局。 | 常用于预后、危险因素和真实世界研究。 |
| 诊断准确性研究 | 评价某项检查是否能正确识别疾病。 | 常需要与参考标准比较。 |
| 预后研究 | 研究患者未来会发生什么及其预测因素。 | 例如出院后再入院风险预测。 |
| 病因学研究 | 研究某种暴露、因素与疾病或结局之间的关系。 | 通常不是直接证明因果，需要谨慎解释。 |
| 真实世界研究 | 使用日常医疗环境中的观察性数据开展研究。 | 需要特别说明数据质量、混杂控制和适用范围。 |
| 研究方案（Protocol） | 研究开始前写清楚目的、方法、对象、结局和分析计划的文件。 | 写作 Agent 可生成草稿，不能代替伦理或正式注册文件。 |
| 报告规范（Reporting Standard） | 某类研究推荐遵循的报告清单或结构。 | 研究设计蓝图会提示适用规范，帮助避免漏项。 |
| 可行性（Feasibility） | 这个研究在时间、病例、人员和资源上能不能做成。 | Agent 会根据可招募人数等信息给出草案判断。 |
| 创新性 | 相比已有研究的新问题、新人群、新方法或新场景。 | 是立项论证的一部分，不能只靠口号。 |
| 去标识化数据 | 已删除或替换能直接识别个人的信息的数据。 | 输入 Agent 前必须去标识化；不要给姓名、住院号、身份证号、电话等。 |
| 汇总数据 | 只提供总体数量、比例、均值等，不含个人记录。 | 适合用于演示、样本量和方案讨论。 |
| PHI | Protected Health Information，受保护健康信息。 | 项目要求不把可识别健康信息传给模型或 MCP 工具。 |

## 9. 专业术语词典：样本量、随机化与统计

| 术语 | 白话解释 | 在本项目里怎么用 |
|---|---|---|
| 样本量（Sample Size） | 为得到有意义结果，大致需要纳入多少研究对象。 | 当前 MVP 计算基础两组比较样本量。 |
| 两组率比较 | 比较两组“发生某事件的比例”。 | 例如比较干预组和对照组的再入院率。 |
| 两组均值比较 | 比较两组某个连续指标的平均值。 | 例如比较两组生活质量评分均值。 |
| 等比例分配 | 两组计划纳入的人数相同或接近。 | 当前样本量工具的前提条件之一。 |
| 对照组事件率 | 对照组预计发生结局的比例。 | 是两组率样本量计算的重要假设，需研究者/统计师确认。 |
| 预期效应 | 希望或预期观察到的差异大小。 | 不能随意填写，应有前期数据或文献依据。 |
| alpha（α） | 统计上允许“把没有差异误认为有差异”的风险阈值。常见设为 0.05。 | 样本量结果会展示该假设。 |
| 把握度（Power） | 当真实差异存在时，研究成功检出的概率。常见设为 80% 或 90%。 | 样本量结果会展示该假设。 |
| 随机化（Randomization） | 用随机规则分配受试者，尽量减少组间系统性差异。 | RCT 才使用；先保存计划，批准后才生成受保护分配表。 |
| 随机分配表 | 具体到每个序号应进入哪一组的表。 | 属于受保护内容，Agent 不会在对话中展示。 |
| 分配隐藏（Allocation Concealment） | 在入组前不让招募者知道下一位受试者会分到哪一组。 | 用于避免人为影响分组。 |
| 置信区间（CI） | 表示效应估计不确定范围的区间。 | 后续证据评价中会保留文章报告的 CI；不会凭空生成。 |
| P 值 | 在某种统计假设下，观察到当前或更极端结果的概率指标。 | 不能单独判断临床意义，应结合效应量、CI 和研究质量。 |
| 效应量（Effect Estimate） | 描述两组差异大小的指标。 | 只有摘要或全文明确报告时才能记录。 |
| RR | Risk Ratio，风险比；两组事件风险的比值。 | 是当前二分类 Meta 分析支持的效应指标之一。 |
| OR | Odds Ratio，比值比；两组事件发生优势的比值。 | 是当前二分类 Meta 分析支持的效应指标之一。 |
| HR | Hazard Ratio，风险比率/危险比，常用于生存时间分析。 | 当前 MVP 不将 HR 纳入 Meta 合并。 |
| 失访 | 研究对象在随访中无法获得结局信息。 | 设计阶段应估计并在样本量中预留。 |

## 10. 专业术语词典：文献检索与系统综述

| 术语 | 白话解释 | 在本项目里怎么用 |
|---|---|---|
| 文献综述 | 对某一问题已有研究进行系统或叙述性的整理。 | 文献综述 Agent 负责检索、导入、去重、初筛支持和总结。 |
| 系统综述（Systematic Review） | 预先设定问题和方法，并尽量完整、透明地检索和评价证据的综述。 | 本项目提供其关键流程支持，但最终方法质量仍需研究者把关。 |
| 检索策略（Search Strategy） | 在数据库中使用的完整检索式和限制条件。 | 由 Agent 生成草案并经 search-agent 优化。 |
| 关键词 | 用于检索的自然语言词。 | 例如“heart failure”“transitional care”。 |
| 同义词扩展 | 把同一概念的不同说法一起加入检索。 | 可减少因措辞不同而漏检。 |
| 布尔逻辑（Boolean Logic） | 用 AND、OR、NOT 连接检索词。 | AND 缩小范围，OR 扩大同义词范围，NOT 需谨慎使用。 |
| PubMed | 美国国立医学图书馆提供的生物医学文献检索数据库。 | 在线/自动模式可经统一后端检索。 |
| Europe PMC | 包含生命科学与医学文献的开放检索平台。 | 在线/自动模式可作为补充来源。 |
| 题录（Citation/Record） | 一篇文献的基本记录，如标题、作者、年份、摘要、DOI。 | 先导入题录，再做去重和筛选。 |
| 元数据（Metadata） | 描述文献的信息，不等于全文内容。 | 如标题、作者、期刊、年份、DOI、PMID。 |
| DOI | Digital Object Identifier，数字对象唯一标识符。 | 用于定位论文和去重，但不等同于本地 `citation_id`。 |
| PMID | PubMed Identifier，PubMed 题录编号。 | 用于引用定位或元数据核验，不能当作本地项目的 `citation_id`。 |
| 本地 `citation_id` | 项目导入后为题录生成的内部编号。 | 提交纳入/排除决定时必须使用它。 |
| 全文（Full Text） | 论文完整正文，而非标题或摘要。 | 全文抽取仅能使用研究者提供、公开可访问或离线包允许的资源。 |
| 开放获取（Open Access） | 可公开、合法访问的全文。 | `fulltext-fetcher` 只能获取这类公开资源，不能绕过付费墙。 |
| 去重（Deduplication） | 识别同一篇文献在不同数据库或文件中重复出现的记录。 | 题录导入后必须执行，避免一篇文章被重复计数。 |
| 初筛（Screening） | 根据标题和摘要初步判断是否可能符合标准。 | screening-agent 只给建议，研究者确认后才保存决定。 |
| `include` | 研究者确认纳入。 | 只有这些文献能进入证据抽取。 |
| `exclude` | 研究者确认排除。 | 应保留排除理由，便于追溯。 |
| `human_review` | 证据不足或有争议，暂时由人工进一步判断。 | 不会被直接当作纳入文章。 |
| PRISMA | 系统综述常用的透明报告框架，常以流程图呈现文献从检索到纳入的数量。 | 当前输出 PRISMA 快照；最终流程图可在数据完整后生成。 |
| 检索量（Records Retrieved） | 数据库检索返回的记录数量。 | 不等于最终纳入研究数。 |
| 导入量（Records Imported） | 实际写入本地综述项目的记录数量。 | 会受每次选择的候选题录范围影响。 |
| 离线证据包（Offline Evidence Package） | 预先准备在本地的原始题录和允许使用的全文资源包。 | 医学数据库不可访问时使用，后续流程仍是导入、去重、筛选、抽取。 |

## 11. 专业术语词典：证据抽取与系统评价

| 术语 | 白话解释 | 在本项目里怎么用 |
|---|---|---|
| 证据抽取（Evidence Extraction） | 按统一表格从每篇文章中摘录研究信息和结果。 | 证据抽取 Agent 的核心工作。 |
| 证据依据（Evidence Basis） | 某个抽取字段到底来自哪里。 | 当前严格标为 `metadata`、`abstract` 或 `full_text_excerpt`。 |
| `metadata` | 仅来自题录基本信息。 | 可说明题目、作者、年份；通常不足以支持效应量或方法结论。 |
| `abstract` | 来自论文摘要。 | 可提取摘要明确报告的设计和结果，但仍不等于全文。 |
| `full_text_excerpt` | 来自研究者提供或合法取得的全文片段。 | 可支持更细的基线、结局和方法抽取。 |
| `not_reported` | 原文没有报告该项。 | 系统会这样标记，不能把缺失猜成“没有发生”。 |
| 基线特征（Baseline Characteristics） | 研究开始时各组患者的年龄、性别、病情、合并症等情况。 | 用于判断组间是否可比和研究对象是否适用于你的场景。 |
| 时间点（Timepoint） | 结局在何时测量。 | 如 30 天、90 天、6 个月；不同时间点通常不能直接混在一起合并。 |
| 文献安全检查 | 查询文献是否出现撤稿、关注声明等明显警示。 | 结果只代表检查当时的状态。 |
| 撤稿（Retraction） | 期刊正式撤回已发表论文。 | 发现撤稿或相关警示时应由研究者重新判断是否使用。 |
| 偏倚风险（Risk of Bias） | 研究设计、实施或报告方式是否可能系统性扭曲结果。 | Agent 只能给出带理由和定位的初步评价。 |
| RoB 2 | Cochrane 面向随机对照试验的偏倚风险评价工具。 | 用于 RCT 的初步评价。 |
| NOS | Newcastle-Ottawa Scale，常用于队列或病例对照研究质量评价的量表。 | 用于队列研究的初步评价。 |
| QUADAS-2 | 诊断准确性研究的质量/偏倚风险评价工具。 | 用于诊断准确性研究的初步评价。 |
| 参考标准（Reference Standard） | 诊断研究中被视为判断真值的标准方法。 | QUADAS-2 评价中常需要核对。 |
| 敏感度（Sensitivity） | 真正有病的人中，被检查正确识别出来的比例。 | 诊断研究的重要指标；当前 MVP 不做诊断准确性 Meta 合并。 |
| 特异度（Specificity） | 真正无病的人中，被检查正确判为无病的比例。 | 与敏感度配合解释诊断表现。 |
| Meta 分析 | 将多项可比研究的结果按统计方法合并。 | 当前只合并可比的二分类 RR 或 OR，且至少两篇。 |
| 森林图（Forest Plot） | 图形化展示每项研究效应及合并效应的图。 | 满足二分类 Meta 条件时生成。 |
| 异质性（Heterogeneity） | 不同研究结果不一致的程度及来源。 | 解读 Meta 结果时需关注；不能因有合并值就忽略差异。 |
| 系统评价包 | 包含证据表、全文来源、初评和可选 Meta 结果的可导出集合。 | 只有对当前精确范围完成研究者确认后才能导出。 |

## 12. 专业术语词典：写作、审批与可追溯性

| 术语 | 白话解释 | 在本项目里怎么用 |
|---|---|---|
| 草稿（Draft） | 可供修改和复核的初版文本。 | Agent 生成的所有方案、标书和讨论文本默认都是草稿。 |
| 方法学（Methods） | 说明研究如何做：对象、设计、变量、流程、分析等。 | 写作 Agent 可基于已保存事实起草。 |
| 讨论（Discussion） | 解释研究发现的意义、局限和与已有证据的关系。 | 必须受来源记录约束，不能补造外部比较或临床建议。 |
| 标书/课题申请（Proposal） | 用于申请课题或经费的材料。 | 当前只能生成草案，仍需补充真实依据、团队、预算和审批材料。 |
| 来源清单（Source Manifest） | 记录一份草稿使用了哪些项目、编号和内容。 | 防止文字脱离证据来源；每份草稿必须保存。 |
| 待解决事项（Unresolved Items） | 当前资料不足、需要人工补充或确认的内容。 | 如待补参考文献、预算、伦理批件或统计分析细节。 |
| 占位符（Placeholder） | 暂留位置，提醒后续补齐。 | 比编造一个看似完整的事实更安全。 |
| 人在回路（Human-in-the-Loop） | AI 在关键点停下，由人作决定再继续。 | 文献纳入、样本量、随机化、系统评价和写作导出都需要人工确认。 |
| OpenCode 原生确认（Allow/Deny） | OpenCode 弹出的权限确认窗口。 | 对受保护的最终动作，选择 Allow 才继续，Deny 则停止且不改变项目。 |
| 审批范围（Scope） | 本次允许确认的具体项目内容集合。 | 证据或草稿发生变化后，旧审批会失效，需要重新核对。 |
| 导出包（Bundle） | 将当前项目的结构化结果打包导出。 | 导出的是当前保存状态，不代表已经获伦理或学术审稿通过。 |
| 可追溯性（Traceability） | 能够回查某项结论来自哪个项目、哪篇文献或哪次工具调用。 | 通过项目 ID、题录 ID、来源清单和 Skill 回执实现。 |
| 审计留痕 | 记录做过什么、何时做、基于什么输入。 | 便于复核，也便于演示系统不是只输出一段不可验证的文字。 |

## 13. 新手最短使用路线

1. 在 OpenCode 打开本项目后，从 Agent 下拉菜单选择最贴近当前任务的 Agent。
2. 先用一句话写明研究问题；能提供 PICO、资源和纳排标准时更好。
3. 看输出时优先检查 `Workflow Status`、`Skills Applied`、来源/证据依据和 `Human Confirmation Required`。
4. 看到“建议”“草稿”“待确认”不要直接当结论；先根据临床实际、原文和统计学意见确认。
5. 出现 OpenCode 的 `Allow/Deny` 时，先核对它将执行的范围，再决定是否允许。
6. 需要继续下一步时，提供上一阶段的项目编号，例如综述 `project_id` 或研究设计项目编号；不要只复制聊天中的长段文字。

## 14. 选择哪个 Agent：快速判断

| 你现在的情况 | 优先使用 |
|---|---|
| 有临床想法，但不知道研究怎么立题、怎么设计 | 研究设计 Agent |
| 有研究问题，想查文献并形成可追溯的筛选流程 | 文献检索与综述 Agent |
| 已经确认要纳入哪些文献，想整理数据和评价证据 | 证据抽取与系统评价 Agent |
| 已有研究设计或证据表，想起草方案、标书、方法或讨论 | 科研写作 Agent |
| 只有一篇论文，想快速了解它 | 可先使用文献综述 Agent 的单项检索/题录核验能力；若要抽取研究数据，再进入证据抽取 Agent |

## 15. 使用边界与责任提醒

- 本工作台用于科研辅助，不用于患者诊断、治疗建议或直接临床决策。
- 不输入可识别患者信息；仅使用去标识化或汇总数据。
- 不把题录、摘要级信息误认为全文证据。
- 不把 AI 的纳入建议、偏倚风险初评、样本量计算或写作草稿视作最终结果。
- 不伪造参考文献、DOI、PMID、效应量、伦理审批、注册信息或临床结论。
- 对计划提交、发表、伦理审查或真实临床应用的材料，必须由研究者、统计师及相应授权人员复核。

## 16. 一句话总结

这四个 Agent 的价值不在于“替人写一段看起来专业的话”，而在于把临床科研从问题定义、文献获取、证据整理到写作草稿拆成可保存、可核对、可人工确认的闭环流程。
