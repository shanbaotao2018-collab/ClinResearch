# 证据抽取 Agent 第二阶段：全文系统评价闭环

## 已交付能力

本阶段在原有“题录/摘要证据表 + 撤稿公告核查”之上增加：

1. 合规全文来源登记：研究者提供全文、公开 HTML，或由研究者提供的 PDF 解析结果。
2. 全文结构化抽取：基线字段及二分类结局的两组事件数、总人数、时间点和效应量类型。
3. 偏倚风险初评：RoB 2、NOS、QUADAS-2；每个域必须带全文依据和页码/章节定位。
4. 二分类 Meta 分析：支持 RR 或 OR、固定效应或 DerSimonian-Laird 随机效应、Q、I²、tau² 和 SVG 森林图。
5. 审批与导出：对当前证据范围生成摘要，必须由受保护的研究者审批接口确认后，才可导出全文来源清单、结构化证据、偏倚初评、可用 Meta 结果和森林图。

## 使用顺序

```text
完成筛选与摘要级证据表
  -> 确认纳入研究
  -> 提供公开全文或 PDF/全文文本
  -> 全文来源登记
  -> 基线与结局抽取
  -> 选择偏倚风险工具并记录依据
  -> 有至少两项可比二分类研究时做 Meta
  -> 请求系统评价审批（锁定当前证据范围）
  -> 授权研究者在受保护接口审批
  -> 导出全文系统评价包
  -> 研究者逐项复核与确认
```

## OpenCode 示例

```text
使用 evidence-extraction-agent 对文献项目 32 做全文系统评价。
我已提供两篇 RCT 的 PDF 解析文本。请保存全文来源，抽取基线和 3 年心衰住院的两组事件数，
做 RoB 2 初评；若两项研究的结局定义和时间点可比，以 RR 做随机效应 Meta 分析并导出森林图。
所有字段都必须标注全文页码或章节；缺失值写 not_reported，不能猜测。
```

## 真实边界

- 系统不会绕过付费墙、登录或机构订阅；仅接受研究者提供或公开可访问的全文。
- `fulltext-fetcher` 和 `pdf-extract` 是取材/解析 Skills；后端保存它们产生的可追溯文本和校验值，不把网页或 PDF 当作未经审阅的事实。
- 当前仅支持同一结局、同一时间点、二分类 RR/OR 的合并。HR、连续结局、诊断准确性合并、网络 Meta、亚组与漏斗图仍不在此版本范围。
- RoB 2、NOS、QUADAS-2 和 Meta 结果均为结构化初稿，`needs_human_review=true`，不能直接作为最终系统评价、投稿或临床结论。
- 审批绑定当前全文、抽取、偏倚初评和 Meta 结果的摘要；范围变化后审批自动失效，必须重新请求审批。

## 验证

`tests/test_systematic_evaluation.py` 使用两项虚构但结构完整的 RCT 2×2 数据验证了：全文来源登记、公开来源联系邮箱脱敏、用户文本 PHI 拦截、基线/结局抽取、RoB 2 域完整性、Skill 回执门禁、随机效应 RR 合并、SVG 森林图、审批锁和系统评价包导出。

这只是软件测试数据，不是医学证据或真实临床结论。

公开全文的工具链验收见 [mvp-evidence-extraction-acceptance-2026-07-20.md](mvp-evidence-extraction-acceptance-2026-07-20.md)。
