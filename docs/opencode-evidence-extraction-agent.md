# 文献筛选与证据提取 Agent 使用说明

## 它解决什么问题

它把“已初筛纳入”的文献整理成一张可审阅的证据表，并在获得合规全文后继续形成基线/结局表、偏倚风险初评和有限范围的 Meta 分析，而不是替你做最终系统评价结论。

它会记录每条信息来自哪里：只有题录、摘要，还是你提供的全文摘录。没有明确依据的字段会写成“未报告”，并进入人工复核清单。

## 使用前需要什么

1. 先用文献综述 Agent 建立并完成一个文献项目。
2. 项目中至少有一篇文献已经被研究者确认或记录为 `include`。
3. 从仓库根目录启动 OpenCode，并选择 `evidence-extraction-agent`。

## 你可以这样提问

```text
请对文献项目 32 做证据提取。重点整理研究设计、研究对象、样本量、干预或暴露、对照、结局和效应指标。没有出现在摘要中的内容请标记未报告，不要猜测。
```

## Agent 会做什么

1. 创建一次可追溯的提取运行。
2. 调用“临床研究信息提取”和“方法学提取”Skills。
3. 把每篇已纳入文献保存为结构化证据行。
4. 调用撤稿核查 Skill，并使用 PubMed 的公告类型查询记录检查时状态。
5. 导出 Markdown 或 JSON 证据表，同时附上实际 Skill 调用回执。

## 全文系统评价阶段

当研究者已确认纳入研究、并提供 PDF、全文文字或公开访问 HTML 后，可继续要求：

```text
请对文献项目 32 完成全文系统评价。PDF 解析结果已提供；请抽取基线和心衰住院的两组事件数，使用 RoB 2 初评，并在至少两项 RCT 数据可比时做 RR 随机效应 Meta 分析和森林图。每项判断必须标注全文页码或章节，不能根据摘要补全。
```

系统会依序保存全文来源清单、基线和二分类结局数据、RoB 2/NOS/QUADAS-2 初评，并在数据满足条件时输出 RR 或 OR 的固定/随机效应合并结果和 SVG 森林图。

它不会绕过付费墙或登录限制；全文必须由研究者提供或来自公开来源。当前 Meta 分析只支持可比的二分类 RR/OR 数据，不支持 HR、连续结局、诊断准确性合并、网络 Meta 或亚组分析。

## 你需要理解的三个提示

- `evidence_basis`：信息来源层级。摘要并不等于全文；仅有题录信息时不能填写效应量。
- `not_flagged_at_check_time`：本次 PubMed 查询没有返回撤稿/更正/关注公告标记，不是永久安全证明。
- `needs_human_review`：任何证据行都需要研究者最终对照全文确认。
