# 全文预验证四 Agent 演示案例（V2）

## 使用原则

这三套案例用于稳定验证研究设计、文献检索与综述、证据抽取与系统评价、科研写作四个 Agent。每个包固定 9 篇真实研究；构建时已从 PubMed 导出原始 NBIB 题录，并逐篇取得 Europe PMC `fullTextXML` 原文。只有返回有效 XML 的研究才会进入清单。

它们是可复现的演示检索集，不是正式系统评价的完整检索结果。系统评价时必须按全文内容重新确认纳入、结局可比性和偏倚风险；异质性高时不应强行 Meta 分析。

## 案例 A：心衰出院后远程随访

- 离线包：`hf-remote-follow-up-v2`
- 研究问题：心力衰竭患者出院后接受结构化电话、远程医疗或短信随访，相较常规出院后管理，是否改善再入院、自我管理或生活质量？
- 适合的研究设计：两组优效性 RCT；主要结局可设为 90 天全因再入院。
- 证据抽取：优先提取随访方式、频率、样本量、再入院时间窗、自我管理与生活质量量表。
- 系统评价：使用 RoB 2；只有干预方式、结局定义和随访时间窗足够接近的子集才可做 Meta。
- 写作产物：远程随访研究方案初稿，或“证据概览与实施要点”草稿。

## 案例 B：心衰居家与远程心脏康复

- 离线包：`hf-home-rehabilitation-v2`
- 研究问题：心力衰竭患者接受居家、远程或早期心脏康复，相较常规管理，是否改善运动耐量、生活质量和再入院？
- 适合的研究设计：两组 RCT；主要结局宜先选定一种，例如 6 分钟步行距离、生活质量或 6 个月再入院，不能混为一个主要结局。
- 证据抽取：提取康复构成、训练周期、依从性、功能量表、生活质量和再入院结局。
- 系统评价：使用 RoB 2；按功能结局、生活质量、住院结局分别分层，避免混合合并。
- 写作产物：居家心脏康复试点研究方案与证据综述草稿。

## 案例 C：药师主导用药核对与出院过渡

- 离线包：`pharmacist-medication-reconciliation-v2`
- 研究问题：药师主导的用药核对与出院过渡服务，相较常规流程，是否减少用药差错、药物相关问题或 30 天医疗利用？
- 适合的研究设计：真实世界比较研究或实施研究；如本地有可比对照组，也可设计务实 RCT。
- 证据抽取：提取服务节点、药师干预内容、用药差错定义、30 天再入院/急诊、实施成本与资源投入。
- 系统评价：RCT 用 RoB 2，非随机研究用 NOS；研究对象和结局差异通常较大，以分层叙述为主。
- 写作产物：药师出院用药核对服务的实施研究方案与 SOP 框架草稿。

## 构建与验收

联网构建机执行：

```bash
cd "/Users/shanbaotao/Documents/agent 2"
apps/literature-review-agent/backend/.venv/bin/python \
  scripts/build-offline-evidence-packages.py \
  --output-dir data/offline-evidence-packages
```

构建器会对 Europe PMC 请求限速与重试；若中断，可使用 `--package-id <包名>` 续跑。每份 XML 必须大于 10 KB 且含有 `<article>`，再写入带 SHA-256 的 `manifest.json`。当前三包各 9 篇、合计 27 篇，已通过本地文件和 XML 结构检查。
