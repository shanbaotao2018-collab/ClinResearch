# 科研写作与方案成稿 Agent 使用说明

## 它解决什么问题

它把已保存的研究设计或已完成的证据表，整理成可继续修改的研究方案、项目申请书初稿、方法学章节或讨论框架。

它不是“输入一句话就直接交一份可投标书”的黑盒。每份草稿都记录来源项目、版本、未解决问题和外部审批状态，避免把模型补全内容误当成真实研究结论。

## 使用前需要什么

选择以下任一种来源：

1. 已保存主要结局和方案大纲的 `study_design` 项目。
2. 已完成每篇纳入文献证据提取的 `review` 项目。

然后指定文稿类型：`protocol`、`proposal`、`methods` 或 `discussion`。

## 你可以这样提问

```text
基于 study_design 项目 15，生成 protocol 类型的研究方案初稿。
面向科室科研讨论会。没有确认的数据不要补写，请放进待确认事项。
```

## Agent 会做什么

1. 检查来源项目是否具备写作所需的已保存内容。
2. 调用大纲、方法学和讨论写作 Skills；写课题申请书时额外调用课题方案生成 Skill。
3. 保存一份带来源清单和版本号的草稿。
4. 请求外部人工审批并停止，不会自行批准。
5. 获得授权审批后，导出带 Skill 执行回执和限制说明的 Markdown 或 JSON 文稿包。

## 使用时要注意

- “已导出”只表示已完成系统流程，不表示伦理、统计、基金或投稿审批已经通过。
- 缺少结果、引用、预算或研究细节时，系统应写入 `unresolved_items`，不能猜测补齐。
- 每次修改应生成新版本，并重新走审批。
