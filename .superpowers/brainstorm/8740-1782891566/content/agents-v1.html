文献综述智能体 MVP：Agent 分工与职责边界

原则：让 Agent 负责“需要医学语言理解和解释”的部分，让规则流负责“确定性的流程状态和统计记账”

推荐模式：1 个总控 Agent + 4 个专用子 Agent

总控 Agent 负责流程推进、状态切换、人工确认节点、结果汇总。

子 Agent 只做单一任务，不跨越职责边界。

1. 选题拆解 / 检索式 Agent

输入：研究问题、PICO、纳排标准草稿

输出：PubMed 检索式、中文关键词串、检索说明

适合 Agent 的原因：需要医学概念拆解、同义词扩展、布尔逻辑解释

2. 检索执行 Agent

输入：确认后的检索式、目标数据库

输出：题录集合、来源标签、时间戳、检索报告

适合 Agent 的原因：负责调工具并解释结果差异，但不做自由决策

3. 去重筛选 Agent

输入：题录集合、纳排标准

输出：候选纳入/排除建议、排除理由草稿、待人工复核列表

适合 Agent 的原因：标题摘要的语义判断需要模型，但最终结论要留给人工

4. PRISMA 汇总 Agent

输入：各阶段计数、纳排日志

输出：PRISMA 数据表、流程图说明、过程摘要

适合 Agent 的原因：负责把确定性统计结果解释成人能读懂的项目总结

哪些交给 Agent

研究问题拆解

同义词/主题词扩展

检索式解释与优化建议

标题摘要语义判断建议

排除理由草稿生成

PRISMA 过程摘要解释

哪些必须固定成规则流

项目状态机

题录去重规则

筛选阶段计数

纳排日志记账

导出文件结构

审计日志

关键设计原则

原则 1：Agent 只提供“建议”和“解释”，不直接替代研究者做最终纳排决策。

原则 2：凡是会进入 PRISMA 统计和审计日志的数据，都必须由规则流记录，不由 LLM 自己记忆。

原则 3：子 Agent 彼此之间不共享自由文本状态，只共享结构化项目状态。
